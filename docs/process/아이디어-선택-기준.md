# LG Home AI 아이디어 — 판단 기준 + 현재 서비스 지도 + 후보 비교

## 1. 판단 기준

**1단계 통과 못하면 제외 → 2단계 정도로 재는 것 → 3단계 무게를 싣는 것(팀 판단)**

### 1단계 — 탈락 기준 (통과 못하면 제외)

- **기준 A. 자사 제품과 겹치는가** — 발주처(LG)가 **이미 팔고 있는 것**을 다시 제안하면 그 자체로 탈락이다.
- **기준 B. 데모로 보여줄 수 있는가** — 유일한 차별점이 아직 없는 하드웨어나 존재하지 않는 데이터에 있어서 지금 시연 자체가 불가능하면 탈락이다. 단, 이 탈락은 나중에 하드웨어·데이터가 생기면 다시 살아날 수 있다.

### 2단계 — 정도로 재는 기준

- **기준 C. AI가 정말 필요한가** — "왜 규칙 기반이 아니라 AI인가"를 보는 기준이다. 여기엔 두 가지 보는 방식이 있다.
  - **불가능성**: 규칙으로는 질적으로 절대 만들 수 없는 경우. 입력이 자유로운 이미지·문장·처음 보는 상황이라 조건-결과 표 자체를 만들 수 없다.
  - **규모성**: 규칙으로 원리상 만들 수는 있지만, 경우의 수가 너무 많아서 그 표를 계속 관리할 수 없는 경우. 학습이 그 관리 부담을 대신한다.
  - 핵심 관찰: "AI답다"고 불리는 서비스 대부분은 사실 규모성 쪽이고, 진짜 불가능성은 생성·인식·자유대화처럼 정해지지 않은 입력을 다루는 서비스에 많다.
  - *우리는 이번 심사에서 규모성까지를 정당한 AI 후보로 보는 방향으로 이미 의견을 모았다. "어느 선까지 규모성을 인정할지"는 2번 지도를 보면서 팀이 더 정교화할 부분이다.*
- **기준 D. 데이터를 확보할 수 있는가** — 그 학습을 돌릴 데이터가 공개되어 있는지. 데모 실현성과 바로 연결된다.
- **기준 E. 실제로 구현할 수 있는가** — 데모를 넘어서 실제로 무엇을, 어떤 기술로 만드는지. 우리는 안을 고르는 동시에 직접 만드는 입장이라 이 기준이 따로 필요하다.

### 3단계 — 무게를 싣는 기준 (탈락은 아니지만 팀 판단에 따라 무게가 실림)

- **기준 F. LG 전략에 맞는가** — 팀 코멘트에서 나온 "락인 생태계, 감정 자동화, 그리고 사소하거나 구현이 쉬운데 사용자에게 편익을 주는 것을 선호한다"는 기준. 이 기준을 그대로 채택할지는 팀 판단이다.
- **기준 G. 경쟁사와 차별되는가** — 팀 코멘트에서 나온 "경쟁사(다이킨) 차별점 — 단순 하드웨어 기업이면 안 됨"이라는 기준.
- **기준 H. 팀이 얼마나 공감하는가** — 코멘트 수·동의자 수로 나타나는 관심도.

> 3단계(F~H)의 무게 배분 — 실현 가능성에 무게를 둘지, 팀 공감·심사 가치에 무게를 둘지 — 은 이 문서가 정하지 않는다. 팀 판단이다.

## 2. 현재 AI 서비스들은 이 기준 어디에 서 있는가

대표적인 실제 AI 웹/제품 서비스를 기준 C(AI가 정말 필요한가)의 두 축 위에 놓아 봤다.

| 서비스 (대표) | 유형 | 왜 이 유형인가 |
|----------|------|------------|
| 스팸 필터·이상거래 탐지 (Gmail, 카드사) | 규모성 | 패턴은 유한하지만 계속 변형되어 조건표를 사람이 못 따라간다. 학습이 유지보수를 대신한다 |
| 추천 (Netflix·Spotify·YouTube) | 규모성 | 원리상 "본 것과 비슷한 것"이라는 규칙이지만, 사용자×콘텐츠 조합이 너무 많다 |
| 광고 타겟팅·랭킹 (Google/Meta) | 규모성 | 위와 같은 구조 — 조합이 너무 많아지는 유형 |
| 요금 변동 대응 냉난방 (tado°·Homey) | 규모성 | 가격 예측은 이미 성숙한 통계이고 결정은 규칙에 가깝다 — **우리 에어컨 안과 같은 유형** |
| 번역 (DeepL·Google Translate) | 회색 → 불가능성 | 문장이 무한히 다양해서 조건표 자체를 만들 수 없다 |
| 음성인식 (Whisper·Siri) | 회색 → 불가능성 | 소리 파형을 텍스트로 바꾸는 건 규칙으로 만들 수 없다 |
| 검색+답변 생성 (Perplexity 등) | 회색 | 검색 자체는 성숙한 정보검색(규모성)이지만, 종합·인용문 생성은 불가능성 쪽이 얹힌다 |
| 처음 보는 취향 학습 (콜드스타트 개인화) | 회색 | "처음 보는 취향·신규 아이템"이 정해지지 않은 입력이라 조건표를 만들 수 없다 — **우리 옷장 안이 여기** |
| 이미지 생성 (Midjourney·DALL·E) | 불가능성 | 텍스트→이미지를 규칙으로 만들 수 없다 |
| 대화형 AI (ChatGPT·Claude·Gemini) | 불가능성 | 자유로운 언어를 주고받는 건 원리적으로 조건표가 불가능하다 |
| 코드 생성 (Copilot·Cursor) | 불가능성 | 자연어+맥락→코드, 열린 생성이다 |
| 임의 사진 인식·설명 | 불가능성 | 정해지지 않은 장면을 보고 문장을 만든다 (다만 정해진 종류만 구분하는 경우는 규모성 쪽으로 내려간다) |
| 단백질 구조 예측 (AlphaFold) | 불가능성 | 서열을 3D 구조로 바꾸는 규칙 모델 자체가 없다 |
| 자율주행 인지 (Waymo 등) | 인지=불가능성 / 제어=규모성 | 카메라로 사물을 인식하는 건 불가능성, 경로를 결정하는 건 규칙에 가깝다 — 같은 서비스 안에서도 층마다 갈린다 |

**지도가 말하는 것**: 왼쪽(규모성)일수록 만들기는 쉽지만 "왜 AI인가"를 방어하기 어렵고, 오른쪽(불가능성)일수록 AI가 필요한 이유는 분명하지만 데이터·시연 난이도가 크다. 우리 두 생존 후보(에어컨·옷장)는 **둘 다 규모성~회색 구간**에 있다 — 그래서 "왜 AI인가"가 계속 걸리는 지점이고, 팀에 솔직하게 공유해야 할 긴장이다.

## 3. 우리 후보 4개 비교

| 기준 | 냉장고 ERP | 베이비 로그 | 유럽 에어컨 (B2C) | 스마트 옷장 |
|---|---|---|---|---|
| 자사 제품과 겹치는가 | **정면으로 겹침** — LG InstaView ThinQ가 CV+LLM으로 식재료 인식·식단 제안을 이미 상용화 | 해당 없음 | 부분 겹침 — "요금 변동에 자동 반응"이라는 카테고리 자체는 Homey가 2025년 8월부터 기본 제공, LG Modbus 앱(2026-02)으로 자사 히트펌프 로컬 연동도 가능. 다만 tado°식 정확한 선제 냉방 기능까지 겹치는지는 문서상 미확인 | 낮음 — 경쟁 앱(Acloset·Whering 등)엔 가전 연동이 없음. LG Styler는 있으나 인식·추천 기능이 아님 |

| 데이터를 확보할 수 있는가 | 중간 — 일반 음식 데이터는 풍부, 냉장고 내부 전용 데이터는 적으나 보강 가능 | 절반 — 울음 감지는 풍부, 수유·수면·배변을 묶은 데이터는 없음 | **최상** — 전력가격, 예측 벤치마크, 재실 감지, 냉매 누출 데이터 모두 공개되어 있음 | 절반 — 옷 궁합·핏 데이터는 풍부하고 공개되어 있음. "내 취향·착용 횟수" 데이터는 공개된 것이 전혀 없어 자체 수집이 유일한 방법 |
| 실제로 구현할 수 있는가 | 중간 — 소규모 냉장고 데이터+인식 모델+재고 상태 관리로 데모는 가능하나 인식 정확도가 관건 | 갈림 — 울음 감지는 즉시 데모 가능, 수유·수면·배변 융합은 데이터·하드웨어 부재로 어려움 | **최상** — 공개 데이터만으로 수일 내 데모 구성 가능 | 상 — 추천 부분은 기존 모델을 그대로 재사용해 며칠 내 가능, 개인 취향 학습 부분만 자체 수집이 필요 |
| LG 전략에 맞는가 | 락인 효과는 강하나 자사 겹침 문제로 의미가 없음 | 락인 효과 있음 | LG가 유럽 냉난방(히트펌프)에 투자 중이고 원격 제어·에너지 모니터링 등 인접 기능은 갖췄음. 정확히 이 기능만 비어 있는 자리로 보임 | Styler가 있으나 이 아이디어와 직접 연결되지 않음 (단 세탁기·스타일러 연동 아이디어로 보완 가능) |
| 경쟁사와 차별되는가 | 삼성 Family Hub도 2025년 신선 37종+포장 50종 인식에 Gemini를 탑재 — 차별 없음 | Nanit·Cubo AI·Owlet(미국 식약청 승인)이 바이탈·수면·울음 기능을 이미 채우고 있음 | 다이킨은 스스로를 하드웨어(공조기기) 제조업체로 정의하고 있어 소프트웨어 쪽 차별 여지는 있음. 다만 tado°가 이미 비슷한 서비스를 팔고 있음 | 경쟁 앱은 있으나 가전 연동이 없음 — 그 지점이 차별 여지 |

> 참고: 위 '데이터를 확보할 수 있는가'는 데이터가 공개되어 있는지를 기준으로 한 것이다. 그 공개 데이터가 상업적 데모에 쓸 수 있는 라이선스인지는 아직 확인하지 않았다 — 후보를 좁힌 뒤 확인이 필요하다.

## 4. 어디로 가야 할지

- 냉장고와 베이비는 이미 위 1단계 탈락 기준에 걸려 있다. 냉장고는 자사 겹침, 베이비는 데모 불가능(단, 데이터·하드웨어가 생기면 다시 검토할 수 있는 탈락이다).
- 남은 두 안(에어컨·옷장)은 정반대의 강약 구조를 가진다. **에어컨은 만들기는 쉽지만 팀 공감대와 "왜 AI인가"에 대한 방어가 약하다. 옷장은 팀이 좋아하지만 만들기가 상대적으로 어렵다**(캡처 하드웨어 미해결·취향 데이터 수집 기간 필요).
- 현재 선택 범위는 이 네 안으로 좁혀져 있다 (다섯 번째 안이나 두 안의 결합을 열어둘지는 팀이 다시 판단할 수 있다).
- 결국 팀이 정해야 할 것: **실현 가능성과 팀 공감·심사 가치 중 어디에 무게를 둘 것인가**, 그리고 **최종 후보를 무엇으로 할 것인가**. 이 문서는 그 판단에 필요한 재료만 놓는다.
