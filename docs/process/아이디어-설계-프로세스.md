# 💡아이디어 설계 프로세스

> **좋은 프로젝트는 "가전을 선택하는 것"에서 시작하지 않는다.**
> **"집에서 어떤 삶을 만들 것인가?"에서 시작한다.**

이 프로세스는 아이디어를 제한하기 위한 것이 아니라, 떠올린 아이디어를 구체화하고 스스로 평가하기 위한 기준이다.
아이디어를 처음부터 완벽하게 만들 필요는 없다. 각 단계의 질문에 답하면서 부족한 부분을 발견하고 보완하면 된다.

---

## 1️⃣ 프로젝트의 방향을 한 문장으로 정의하기

### 🎯 질문

> **우리 프로젝트가 만들고 싶은 스마트홈은 어떤 모습인가?**

처음에는 완벽한 문장보다 우리가 나아갈 방향을 정하는 것이 중요하다. 아이디어가 구체화되면 마지막에 이 문장을 다시 수정한다.

### 예시

- 집을 이해하는 AI
- 생활을 예측하는 AI
- 가족의 행동을 변화시키는 AI
- 집의 리듬을 읽는 AI
- 사용자의 하루를 준비하는 AI
- 보이지 않는 위험을 먼저 발견하는 AI

### 📌 LOCUS — 2025년 1등

> **당신의 집을 이해하는 AI**

집 안의 생활 맥락을 이해하고 오염 가능성을 예측하여 로봇청소기가 선제적으로 행동한다.

### 📌 HomeQuest — 2025년 2등

> **일상을 챌린지로, 집을 경험으로**

스마트홈 데이터를 가족의 행동 변화로 연결하여 가사·절약·건강 활동을 유도한다.

> ⚠️ "집을 이해하는 AI"처럼 멋진 표현을 만드는 것만으로는 충분하지 않다.
> 뒤의 단계에서 **누구의 어떤 문제를 어떻게 해결하는지** 구체화해야 한다.

---

## 2️⃣ 대상 사용자와 생활 장면 찾기

### 🎯 질문

> **누구의, 어떤 순간을 더 좋게 만들고 싶은가?**

"모든 가정"을 위한 아이디어는 문제와 기능이 모호해지기 쉽다. 먼저 사용자가 실제로 불편을 겪는 구체적인 순간을 떠올린다.

### 사용자 예시

- 1인 가구
- 맞벌이 부부
- 어린 자녀가 있는 가족
- 노인과 함께 생활하는 가족
- 집에서 공부하거나 근무하는 사람
- 여러 명이 함께 생활하는 가정

### 생활 장면 예시

- 출근 준비로 바쁜 아침
- 귀가한 직후
- 요리하거나 식사한 뒤
- 가족이 모두 외출한 시간
- 잠들기 전과 수면 중
- 집에 손님이 방문했을 때

### 📌 LOCUS

- **사용자:** 반복적인 청소 부담을 줄이고 싶은 가정
- **생활 장면:** 요리하거나 간식을 먹어 오염이 발생할 가능성이 높은 순간

### 📌 HomeQuest

- **사용자:** 가사 분담과 생활 습관 개선이 필요한 가족
- **생활 장면:** 가전을 사용하거나 집안일을 수행하는 일상적인 순간

> 좋은 아이디어는 보통 **"누구나 가끔 겪는 문제"보다 "특정 사용자가 자주 겪는 문제"**에서 나온다.

## 3️⃣ 생활 문제와 만들고 싶은 가치 정의하기

### 🎯 질문

> **사용자는 현재 무엇이 불편하며, 이 문제가 해결되면 무엇이 좋아지는가?**

가전의 부족한 기능이 아니라 사람의 생활 문제를 정의한다.

### ❌ 가전 중심 문제

- 냉장고에 AI 기능이 부족하다.
- 공기청정기가 사용자를 잘 이해하지 못한다.
- TV를 더 편리하게 제어하고 싶다.

### ✅ 생활 중심 문제

- 반복되는 집안일이 언제 필요한지 매번 직접 확인해야 한다.
- 가족 구성원마다 원하는 환경이 달라 갈등이 생긴다.
- 집 안에서 발생하는 작은 위험을 사용자가 항상 확인하기 어렵다.
- 스마트홈 데이터는 많지만 실제 생활 개선으로 이어지지 않는다.

### 만들 수 있는 생활 가치

- 시간을 절약한다.
- 반복적인 부담을 줄인다.
- 사고나 위험을 예방한다.
- 가족의 소통과 협력을 돕는다.
- 에너지와 비용을 절약한다.
- 더 건강하고 규칙적인 생활을 돕는다.

### 📌 LOCUS

**문제**
로봇청소기는 사용자의 명령이나 정해진 일정에 의존하기 때문에, 생활 중 동적으로 발생하는 오염에 대응하지 못한다.

**가치**
사용자가 직접 청소 시점과 장소를 판단하지 않아도 집이 먼저 상황을 이해하고 청소한다.

### 📌 HomeQuest

**문제**
스마트홈 데이터는 계속 쌓이지만 사용자의 실제 행동 변화로 이어지지 않는다.

**가치**
가전 데이터를 챌린지와 보상으로 전환하여 가족의 가사 분담과 생활 습관 개선을 돕는다.

## ✅ 확인하기

- 실제 사용자가 반복적으로 겪는 문제인가?
- 현재는 어떤 방법으로 해결하고 있는가?
- 해결되었을 때 사용자가 체감할 변화가 있는가?
- 가능하다면 주변 사용자에게 실제로 불편한지 확인했는가?

## 4️⃣ AI의 핵심 판단 정의하기

### 🎯 질문

> **AI는 사용자를 위해 어떤 판단을 내려야 하는가?**

하나의 프로젝트에 여러 AI 기술이 들어갈 수 있지만, 사용자를 위해 내리는 **핵심 판단은 하나로 설명할 수 있어야 한다.**

### AI 역할 예시

- **예측:** 다음에 어떤 일이 발생할 것인가?
- **추천:** 지금 어떤 행동이 가장 적절한가?
- **추론:** 현재 어떤 상황인가?
- **감지:** 평소와 다른 이상 상태가 발생했는가?
- **조율:** 여러 사람이나 가전의 요구를 어떻게 맞출 것인가?
- **기억:** 과거의 생활 패턴을 현재 판단에 어떻게 반영할 것인가?

### 📌 LOCUS

> **"지금 어느 공간에 오염이 발생할 가능성이 높은가?"**

객체·자세·소리·위치·시간 정보를 분석하여 청소할 장소와 시점을 예측한다.

### 📌 HomeQuest

> **"누구에게 어떤 챌린지를 언제 제안해야 참여 가능성이 높은가?"**

가전 사용 패턴과 과거 수행 기록을 분석하여 개인별 챌린지를 추천한다.

## ✅ 확인하기

> 우리 AI가 내리는 판단을 하나의 질문으로 표현할 수 있는가?

## 5️⃣ AI가 이해해야 하는 Context와 데이터 정의하기

### 🎯 질문

> **AI가 올바르게 판단하려면 무엇을 알아야 하는가?**

### 👤 사람

- 누구인가?
- 몇 명인가?
- 어떤 선호와 생활 패턴을 가지고 있는가?

### 🚶 행동

- 무엇을 하고 있는가?
- 평소와 다른 행동이 있는가?

### 🏠 공간

- 어느 방에 있는가?
- 공간이 현재 어떤 상태인가?

### ⏰ 시간

- 언제인가?
- 평일과 주말의 패턴이 다른가?

### 🌡 환경

- 온도, 습도, 공기질, 조도, 소음은 어떤가?

### 🌤 외부 정보

- 날씨, 일정, 교통, 전기요금 등 외부 상황은 어떤가?

### 📱 가전·IoT 데이터

- 어떤 가전이 작동했는가?
- 언제, 얼마나 사용했는가?
- 사용 전후의 상태가 어떻게 달라졌는가?

### 📌 LOCUS

사람의 자세 + 주변 객체 + 생활 소리 + 위치 + 시간
↓
**현재 생활 맥락과 오염 가능성 이해**

### 📌 HomeQuest

가전 사용 로그 + 가족 활동 + 챌린지 수행 기록
↓
**가족 구성원별 행동 패턴 이해**

> Context를 많이 사용하는 것이 항상 좋은 것은 아니다.
> **AI의 핵심 판단에 꼭 필요한 데이터만 선택해야 한다.**

## ✅ 데이터 확인하기

- 이 데이터를 실제로 수집할 수 있는가?
- ThinQ API, 센서, 카메라 또는 사용자 입력 중 무엇을 사용할 것인가?
- 실제 데이터가 없다면 어떻게 시뮬레이션할 것인가?
- 카메라·마이크 사용 시 개인정보 문제는 없는가?

## 6️⃣ AI가 반드시 필요한 이유 설명하기

### 🎯 질문

> **정해진 규칙이나 일반적인 자동화로도 가능한 기능은 아닌가?**

입력 데이터가 많거나 생성형 AI를 사용한다고 해서 반드시 AI가 필요한 것은 아니다.

### ❌ 단순 규칙

```
18시가 되면
↓
에어컨 작동
```

### ⚠️ 복잡하지만 여전히 규칙으로 가능한 경우

```
습도가 70% 이상이고
+
사용자가 거실에 있으면
↓
제습 모드 작동
```

### ✅ AI가 필요한 경우

```
사용자별 생활 패턴
+
최근 행동 변화
+
시간에 따라 달라지는 환경
+
과거 제어에 대한 사용자 반응
↓
사용자마다 다른 적절한 개입 시점과 방법 판단
```

AI는 다음과 같은 상황에서 의미가 있다.

- 사람마다 판단 기준이 다르다.
- 같은 사람도 상황에 따라 원하는 결과가 달라진다.
- 사람이 모든 조건을 규칙으로 정의하기 어렵다.
- 데이터가 쌓일수록 판단이 개선된다.
- 여러 정보 사이의 복잡한 관계를 찾아야 한다.

### 📌 LOCUS

"저녁 7시에는 청소한다"는 규칙이 아니라, 행동·소리·공간·시간을 함께 분석해 오염 가능성을 예측한다.

### 📌 HomeQuest

모든 가족에게 같은 미션을 보내는 것이 아니라, 개인별 수행 패턴을 학습해 참여 가능성이 높은 챌린지를 추천한다.

## ✅ 확인하기

- AI 없이 구현하면 무엇이 부족한가?
- 단순 규칙과 비교했을 때 AI가 더 잘할 수 있는 것은 무엇인가?
- 데이터가 쌓일수록 서비스가 실제로 개선되는가?
- AI의 판단이 틀렸을 때 사용자가 수정하거나 취소할 수 있는가?

## 7️⃣ 가전과 서비스의 행동 설계하기

### 🎯 질문

> **AI가 판단한 뒤 실제로 무엇이 달라지는가?**

이 단계에서 처음으로 필요한 가전을 선택한다.
AI의 결과가 단순한 분석 화면에서 끝나기보다, 사용자의 생활 변화로 이어져야 한다.

### 행동 예시

- 가전을 자동으로 실행한다.
- 여러 가전의 동작을 함께 조율한다.
- 사용자에게 적절한 선택지를 제안한다.
- 위험 상황을 감지하고 필요한 사람에게 알린다.
- 환경을 조절하거나 불필요한 작동을 줄인다.
- 사용자의 피드백을 받아 다음 판단에 반영한다.

### 📌 LOCUS

오염 가능성이 높은 장소와 시점 예측
↓
로봇청소기의 이동과 청소 실행

### 📌 HomeQuest

개인별 참여 가능성이 높은 챌린지 추천
↓
가전 사용 기록으로 수행 여부 확인
↓
포인트·랭킹·보상으로 행동 지속 유도

> **가전은 프로젝트의 주인공이 아니라 AI의 판단을 현실에서 실행하는 수단이다.**

## ✅ LG 연결성 확인하기

- 왜 이 문제를 해결하는 데 LG 가전이 필요한가?
- 여러 가전이나 ThinQ 데이터가 연결될 때 더 큰 가치가 생기는가?
- 이 서비스를 통해 LG 제품과 ThinQ를 사용할 이유가 늘어나는가?

## 8️⃣ 대표 사용 흐름 그리기

### 🎯 질문

> **사용자는 어떤 상황에서 우리 서비스를 경험하게 되는가?**

구체적인 화면이나 시연 방법을 정하는 단계가 아니다. 아이디어가 실제 생활에서 어떻게 작동하고 사용자에게 어떤 변화를 만드는지 하나의 흐름으로 확인한다.

### 기본 흐름

```
생활 문제 발생
↓
Context 수집
↓
AI 판단
↓
가전 또는 서비스의 행동
↓
사용자가 얻는 변화
```

### 📌 LOCUS

사용자가 거실에서 간식을 먹음
↓
자세·객체·소리·위치 정보 인식
↓
거실의 오염 가능성 예측
↓
로봇청소기가 필요한 공간을 청소
↓
사용자가 직접 청소를 지시하는 부담 감소

### 📌 HomeQuest

가족 구성원의 가전 사용 기록 발생
↓
과거 행동과 챌린지 수행 패턴 분석
↓
개인에게 적합한 챌린지 추천
↓
수행 결과가 포인트와 보상에 반영
↓
가사 참여와 생활 습관 개선

## ✅ 확인하기

- 사용자가 서비스를 이용하는 상황이 자연스러운가?
- Context가 AI의 판단과 논리적으로 연결되는가?
- AI의 판단이 실제 가전 또는 서비스의 행동으로 이어지는가?
- 사용자가 얻는 변화가 명확한가?
- 일회성 기능이 아니라 반복해서 사용할 이유가 있는가?

## 9️⃣ 한 학기 안에 완성 가능한지 확인하기

### 🎯 질문

> **우리 팀이 실제로 구현하고 검증할 수 있는가?**

좋은 아이디어라도 데이터나 장비를 확보할 수 없거나 핵심 기능을 시연할 수 없다면 완결성을 얻기 어렵다.

## ✅ 구현 가능성 체크

- 필요한 데이터와 센서를 확보할 수 있는가?
- 실제 가전이 없다면 시뮬레이션할 수 있는가?
- AI의 성능을 평가할 기준이 있는가?
- 네 명의 역할을 명확하게 나눌 수 있는가?
- 한 학기 안에 MVP를 완성할 수 있는가?
- 방학 동안 필요한 역량을 준비할 수 있는가?
- AI가 실패했을 때 사용할 기본 동작이 있는가?

### 역할 분담 예시

- AI·데이터
- 백엔드·IoT 통신
- 프론트엔드·앱
- UX·서비스 기획 및 통합

> 처음부터 거대한 스마트홈 전체를 만들 필요는 없다.
> **핵심 판단과 행동은 실제로 구현하고, 주변 환경은 합리적으로 시뮬레이션할 수 있다.**

---

## 🎯 우리가 만들고자 하는 프로젝트

> **"가전을 제어하는 AI"가 아니라, 집 안에서 살아가는 사람의 상황을 이해하고 더 나은 판단과 행동으로 연결하는 AI**

아이디어를 생각할 때는 **"냉장고로 무엇을 하지?"**가 아니라,

> **"누구의 어떤 생활을 더 좋게 만들고 싶은가?"**

를 먼저 고민한다.

### 최종 설계 순서

> **사용자와 상황 → 생활 문제와 가치 → AI의 핵심 판단 → Context와 데이터 → AI 필요성 → 가전 행동 → MVP와 시연 → 구현 가능성 → 중복 및 점수 평가**
